# 本地学习数据兼容说明

## 已移除与保留

已移除账号注册/登录、个人资料、会员升级、兑换码、云同步，以及四个仅做权限判断的专项占位页面和菜单。普通 `ExamScreen → ExamGeneral`、题库、章节练习、收藏、错题、历史/重做、词典和设置保留。新闻占位、Banner、GitHub 更新检查和发布工作流不在删除范围；“本地化”指学习数据，不代表完全禁止网络。

## 最终归属规则：单一本地模式，无选择器

`LocalStudyData` 为所有学习页提供同一套本地归属解析。SQLite 原 `users.id` 和各学习表 `user_id` 保留，不改写现有学习行、不重建数据库、不合并不同归属。不删除旧 schema 字段，以免破坏旧库和外键兼容；它们不再提供账号/会员功能。历史不再自动裁剪。

首次解析时：
- 有效 `local_study_owner_id` 优先，沿用真实 ID 与原可见范围。
- 没有本地 ID 时，有效明确旧 `username` 沿用其原 ID 与范围。
- 没有明确选择且仅有一个用户、无孤立/NULL 学习归属时，沿用该真实 ID。
- 真正空的新安装创建本地归属，收藏、错题、历史及明细仍为空；之后的新记录均可使用该归属保存。随包题库本身不含 users/学习记录表，但这不代表可以清除已安装数据库。
- 多历史用户、孤立/NULL 归属、失效的用户名/本地 ID 不再阻塞：为**新学习记录**创建独立本地归属。失效本地 ID 不回退到旧用户名或其他用户。没有账号、profile 或数据集选择器。

### 持久性与冲突避免

创建/沿用的归属和 `local_study_state` 单行数据库标记在同一 SQLite 事务提交。新 ID 严格大于 `users.id`、`favorites.user_id`、`wrong_answers.user_id`、`quiz_history.user_id` 的全部现存整数值（包括孤立值和删除标记行）；绝不硬编码 user 1。空库从零以上分配。用户名按 SQLite 查询检查冲突，依次尝试 `local`、`local-<id>`、带序号后缀名称，兼容旧用户名排序规则。ID 达 SQLite 整数上限时明确报错并回滚，不能安全分配时不碰旧行。

数据库标记提交后成为单一本地身份的权威来源；偏好只作为兼容缓存，写入返回 false 或抛异常不阻止学习保存，重试/重启也不重复创建归属或跳回旧用户。无标记的第一次解析若偏好读取失败则报错、回滚并等待重试，以免遗漏有效旧选择。有标记时不依赖偏好读取。若标记对应用户后来已不存在，则创建新的独立归属并原子更新标记，不改其他学习行。

### 历史可见性限制（不是待决迁移）

**旧学习记录原样保留不等于全部可见。** 当前只显示最终本地归属范围内的记录。有效明确旧选择保留原范围；歧义情况下新归属不会自动显示其他用户、孤立或 NULL 归属的历史。服务输出这一兼容限制到诊断日志，本文与 README 同时说明；不新增选择器，也不声称 UI 已提供历史恢复入口。此为用户已授权的最终单一本地模式，不再等待合并/选择器决定。

非常旧的收藏若缺少 section/question 映射，仅做已有补列修复并保留原行；映射恢复仍未解决。未读取真实安装数据库，未执行真实旧库升级。数据库错误仍交给已有页面异常/重试流程；列表不把错误显示成空列表。交卷保存失败时先提示“本次成绩未保存”，再允许仅查看成绩。
